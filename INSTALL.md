# Machine setup (Plane access for Claude)

One-time steps per developer machine (OPS-177). **Each person signs in as themselves. Tokens are never
shared, copied between machines, committed, or pasted into chat.**

Claude reaches the NFCAP board on Plane in one of two ways:

| Your machine           | How Claude talks to Plane                              | Setup               |
| ---------------------- | ------------------------------------------------------ | ------------------- |
| **Windows** (or Linux) | The **Plane MCP** in Claude Code                       | Part A only         |
| **macOS**              | Plane MCP, plus a faster script for `/project-pm sync` | Part A, then Part B |

Part B saves tokens but is macOS-only today. On Windows, `/project-pm sync` uses the Plane MCP instead:
everything works, it is just slower and more expensive.

## Part A: Plane MCP (every machine)

1. Check whether it is already there. In Claude Code, run `/mcp`. If `plane` is listed and connected, go to
   step 3.
2. Add it (in a terminal, not inside Claude):

   ```bash
   claude mcp add --transport http --scope user plane https://mcp.plane.so/http/mcp
   ```

3. In Claude Code, run `/mcp` → `plane` → **Authenticate**. A browser opens: sign in with **your own**
   Plane account on the `zunkireelabs` workspace.
4. Check it: ask Claude "how many open NFCAP tickets are there?". A number means you are done. If you get
   a permission error, you are not a member of the NFCAP project yet: ask Sadin.

## Part B: scripted sync (macOS only)

Lets `/project-pm sync` regenerate `tasks/TRACKER.md` in one shell call instead of many Plane MCP turns.
Background: `tools/plane/README.md` in `Zunkireelabs/zunkireelabs-org`.

### Rules for you and for Claude

- Run these steps **in your own terminal**. Claude may read this file and walk you through it, but it must
  never print, paste or ask for the vault password, an OAuth token, or anything in `~/.mcporter/`.
- If a step fails, paste the **error message** into chat, not the contents of any secret or token file.
- The vault password is generated by the command in step 4 and goes straight into your keychain. You never
  see it, type it, or save it in a file.
- Do not copy `~/.mcporter/` or the keychain item to another machine. Set up each machine again.

### What you need first

- A Mac, a GitHub account with access to `Zunkireelabs/zunkireelabs-org` (it is granted through the
  `zunkiree-dev-team` team), and a Plane account on the Zunkireelabs workspace.
- The Plane MCP server already configured in Claude Code. It is, if you already use Plane from Claude.
  The script reuses that definition; it does not install Plane for you.

### Steps

1. **Get the scripts.** They live in `tools/plane/` of the `zunkireelabs-org` repo, **not in this repo**.
   Your machine may not have it yet. Check:

   ```bash
   ls ~/Projects/zunkireelabs-org/tools/plane/
   ```

   You should see `README.md`, `mcp-run` and `plane-tracker.py`. If the folder does not exist, clone it:

   ```bash
   git clone git@github.com:Zunkireelabs/zunkireelabs-org.git ~/Projects/zunkireelabs-org
   ```

   If you already have a clone but `tools/plane/` is missing, it is out of date:

   ```bash
   cd ~/Projects/zunkireelabs-org && git checkout main && git pull
   ```

   The path matters. `/project-pm sync` and every example below assume `~/Projects/zunkireelabs-org`.
   If the clone fails with a permission error, you are not on the team yet: ask Sadin. Do not work around it.

2. **Node 24 or newer** (the pinned `mcporter` needs it):

   ```bash
   node --version
   ```

   If it prints a lower version, install Node 24 (for example with `nvm install 24`) and open a new terminal.

3. **Make the script runnable** (only if step 5 says "permission denied"):

   ```bash
   chmod +x ~/Projects/zunkireelabs-org/tools/plane/mcp-run ~/Projects/zunkireelabs-org/tools/plane/plane-tracker.py
   ```

4. **Create the vault password in your keychain** (generated for you, never typed, never in a file):

   ```bash
   security add-generic-password -a "$USER" -s mcporter-vault -l "mcporter OAuth vault password" -w "$(openssl rand -base64 32)"
   ```

   If it says the item already exists, you did this before. Skip to step 5. Do not run it twice: a second
   password would lock the vault you already filled.

5. **Sign in to Plane as yourself.** A browser opens; log in with your own account and **wait until the
   command returns**:

   ```bash
   ~/Projects/zunkireelabs-org/tools/plane/mcp-run auth plane
   ```

   macOS may ask to allow keychain access: choose Allow.

6. **Check it works.** This prints a ticket count and nothing else:

   ```bash
   ~/Projects/zunkireelabs-org/tools/plane/mcp-run call plane.workitem action=count --no-oauth
   ```

   A number means you are done. Tokens are stored encrypted in `~/.mcporter/` and renew by themselves.

### Try it on NFCAP

From the root of this repo:

```bash
~/Projects/zunkireelabs-org/tools/plane/plane-tracker.py --project NFCAP \
    --out tasks/TRACKER.md --repo .
```

It prints one summary line and writes `tasks/TRACKER.md`. It only reads Plane. If Plane fails, it writes
nothing. `tasks/TRACKER.md` is generated: never hand-edit it.

### If something goes wrong

| You see                                              | Meaning                                                   | Do                                                |
| ---------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| `keychain item 'mcporter-vault' not found or locked` | Step 4 not done, or the keychain is locked                | Do step 4, or unlock the login keychain           |
| Browser does not open, or sign-in loops              | Plane MCP not configured in Claude Code, or wrong account | Confirm Plane works from Claude, then redo step 5 |
| Step 6 fails after it worked before                  | Token expired and could not renew                         | Redo step 5                                       |
| Node version error                                   | Node older than 24                                        | Step 2                                            |

Still stuck: ask in the team channel and include the error text only.

### Undo

Removes everything this section set up. The Plane MCP in Claude Code is untouched, so `/project-pm sync`
keeps working through it.

```bash
rm -rf ~/.mcporter
security delete-generic-password -s mcporter-vault
```

You may also delete `~/Projects/zunkireelabs-org` if you cloned it only for this.
